# Base Times

Scoring needs a reference time. This package ships one table per course and
season so a caller can name an event instead of a number — and still supply its
own base time whenever it wants to.

## What a base time is

World Aquatics defines a base time as **the world record that stood approved on
the first day of the season's validity period**. It is therefore a snapshot, not
a live record list: a record broken in March does not change that season's
table, it changes the next one.

## Two calendars

Long course and short course run on different seasons, so they are numbered
independently:

| Course       | Season runs             | Base time is the record as of |
| ------------ | ----------------------- | ----------------------------- |
| Long (50 m)  | 1 January – 31 December | 1 January                     |
| Short (25 m) | 1 September – 31 August | 1 September                   |

`long-2025` and `short-2024` overlap in real time. They are not the same season,
and `latest_season` returns a different number for each:

```python
from aqua_points_calculator import Course, available_seasons, latest_season

available_seasons(Course.LONG)  # (2022, 2023, 2024, 2025, 2026)
available_seasons(Course.SHORT)  # (2021, 2022, 2023, 2024, 2025)
latest_season(Course.LONG)  # 2026
latest_season(Course.SHORT)  # 2025
```

## Using them

```python
from aqua_points_calculator import Course, Event, Gender, Stroke, score_for

event = Event(distance=100, stroke=Stroke.FREESTYLE, course=Course.LONG, gender=Gender.MALE)

score_for(event, "51.35")  # against the latest shipped season
score_for(event, "51.35", 2022)  # against a historical one
```

The result records which table it used, so a stored score stays interpretable:

```python
result = score_for(event, "51.35")
result.base_time  # '46.40'
result.season  # 2026
```

A score built from a base time you passed in has `season is None` — it belongs
to no table, and claiming one would misreport where the number came from.

To look a base time up without scoring anything:

```python
from aqua_points_calculator import base_time
from aqua_points_calculator.data import table

base_time(event)  # milliseconds, latest season
base_time(event, 2023)  # milliseconds, that season
table(Course.LONG, 2025).source.url  # the official document behind it
```

## Coverage

Each table covers every individual event and every relay World Aquatics scores,
for men, women and — for relays — mixed.

|              | Long course                  | Short course                 |
| ------------ | ---------------------------- | ---------------------------- |
| Freestyle    | 50, 100, 200, 400, 800, 1500 | 50, 100, 200, 400, 800, 1500 |
| Backstroke   | 50, 100, 200                 | 50, 100, 200                 |
| Breaststroke | 50, 100, 200                 | 50, 100, 200                 |
| Butterfly    | 50, 100, 200                 | 50, 100, 200                 |
| Medley       | 200, 400                     | **100**, 200, 400            |
| Free relay   | 4x100, 4x200                 | 4x50, 4x100, 4x200           |
| Medley relay | 4x100                        | 4x50, 4x100                  |
| Mixed relay  | 4x100 free, 4x100 medley     | 4x50 free, 4x50 medley       |

The 100 m medley is short course only; asking for one in a long-course table
raises `UnknownEventError`, it does not fall back. The 2021 short-course table
predates mixed relays in the official document and has 46 entries rather than 48.

A relay is a separate entry from the individual event of the same distance, and
`legs` is what distinguishes them:

```python
Event(distance=100, stroke=Stroke.FREESTYLE, course=Course.LONG, gender=Gender.MALE, legs=4)
```

## Where the numbers come from

Every table names its source document:

```bash
aqua-points-calculator base-times --course long --season 2025
# long course, season 2025 (2025-01-01 – 2025-12-31)
# World Aquatics Points - Base Times SCM and LCM 2025
```

Eight of the ten tables come from an official _base-times_ publication. World
Aquatics never published one for long course 2022, long course 2024 or short
course 2023, so those three are read from the **1000-point row of the official
point-scoring tables** for the same season — which is the base time by
definition. That equivalence was verified against long course 2025, where both
documents exist: all 17 individual events agree exactly.

## Accuracy

The files are generated by `tools/generate_base_times.py`, not typed by hand,
and three things check them:

1. **Within the source.** Every base-times PDF prints each time twice, as
   `mm:ss.hh` and in seconds. All 356 values were cross-checked; exactly one
   disagreed — the women's short-course 100 butterfly for 2022-23, printed as
   both `54.59` and `54.69`. The point-scoring table for that same season reads
   `54.59` at 1000 points, so that is what ships, and `short-2022.yaml` records
   the discrepancy in a comment.
2. **Within each table.** `tests/unit/test_data.py` asserts over all ten files
   that times rise with distance within a stroke, that the men's time is faster
   than the women's in every event, that every value is a plausible swim, and
   that each validity window matches its course's calendar.
3. **Across tables.** The windows of one course must tile without gaps or
   overlaps.

The second check is the one that would catch the realistic extraction failure —
two columns of a PDF getting crossed.

## When to bypass them

Pass your own base time whenever you need a reference these tables do not hold —
a national record, an age-group standard, a club benchmark, or a season older
than the five shipped:

```python
from aqua_points_calculator import score

score("48.50", "51.35")
```

That path touches no table and needs no season.
